# Codex host discovery smoke

This optional manual check starts two separate installed Codex App Server processes. It uses only `initialize`, `initialized` and `skills/list`, never starts a thread/turn or model task, and never installs a global Skill. Analytics is disabled for these processes using a command-scoped setting. No global configuration is rewritten by this probe.

Use a previously reviewed Paisley development package, not an arbitrary downloaded archive: the probe extracts and executes its installer. This is a test workflow, not a security sandbox. Example from repository root:

```sh
node experiments/weather-report-20261104/host-discovery/probe.cjs REVIEWED_LOCAL_PACKAGE.zip
```

The fixture is a newly created temporary Git project. It asserts that the exact project Skill path is absent before installation, then present/enabled in `repo` scope after an explicit force reload and after restarting the host process. Global same-name Skills cannot satisfy the path assertion. It checks the installed resolver points to the extracted package and prints only filtered proof, not other discovered Skill metadata.

The observed binary is the installed Codex app's CLI; select another reviewed binary with `PAISLEY_CODEX_BIN` when needed. `PAISLEY_HOST_LOG` optionally retains local diagnostics: these may contain private paths and must not be uploaded. The probe canonicalizes macOS temporary paths; `/var` and `/private/var` aliases must not create a false mismatch. It cleans its owned fixture only after confirmed child close; unconfirmed shutdown retains it.

The local protocol schema is generated by `codex app-server generate-json-schema` and agrees with the [official App Server documentation](https://learn.chatgpt.com/docs/app-server#skills). See [local Skill discovery documentation](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills). Protocol/version and scope are part of the evidence: this does not prove a live Desktop chat reloaded its instructions, natural-language task routing, every Codex release, or Windows. A restrictive outer sandbox prevented App Server initialization during the first attempt; the ordinary local process initialized under authorized execution permissions. A resolver result alone remains a different, weaker check.
