# 正式 7.0 与当前 7.1 的隔离情境对照

本阶段只补批准计划 §7.3 的三类实际缺口，不扩大原 12 题，不执行设备或 App 操作。沿用原有 schema、grade、JSONL 检查与一次性 `codex exec` 调用方式。以下约定及 `frozen-inputs.json` 在读取本轮模型回答前冻结。

## 覆盖与参考资料

| 场景 | 本轮处理 |
| --- | --- |
| 已隔离且获授权 | 原 `authorization-unchanged` 题面不变，作为锚点。 |
| 可重建测试副本 | 新增 `isolation-rebuild-copy`；指定副本已有准确重建授权与恢复条件，不能反复审批。原产物清理题没有覆盖 App 重建。 |
| 独立 APK 仍连接真实云 | 原 `authorization-cloud-changed` 题面不变，作为锚点。 |
| App 身份改变 | 新增 `isolation-app-changed`；A/B 均已授权，B 的变化项需核对，A 的绑定不能复用，未变源码证据不必全部重做。 |
| 操作超出授权 | 新增 `isolation-outside-scope`；可重建和隔离事实不能授予删除存档权限。 |

每题可接受行为、禁止行为和结束条件冻结在 `rubric.json`。该文件与 oracle 都不提供给答题模型；Judge 才读取 rubric。两道锚点曾用于旧实验，只有三道新题属于本轮留出样本；它们是按真实反馈构造的情境，不能证明训练集未知。

- 基线：正式 `v7.0.0^{commit}` = `1ff6e254bbd398c26360a25f60121942e8f98e2c`。
- 候选：当前 7.1 RC.2 后的源码 `a701c02659c15af8b7223df32b512f84b2295711`。
- 两组各读取上述提交的完整 `.agents/skills/dol-dev-tools-paisley-park/SKILL.md` 和 `docs/DEVELOPMENT_FLOW.md`。正文通过 `git show` 提取，原始字节、Git blob 与 prompt 摘要保存在冻结清单；不使用未采用长稿。

实际 diff 显示：Skill 的隔离/授权核心原则在 7.0 已存在；7.1 增加官方 Android CLI 选路、改名称和文档入口。Recipe 新增隔离接续与产物责任两段。这里比较整个固定参考包，不将观察到的差异归因于单句修改。

## 运行与评分

两组使用同一受控工作目录、相同 fixture AGENTS、题目、schema、工具可用性和现有宿主配置。保持已配置的 `gpt-6.1-sol / high`，不修改用户配置或权限；CLI 为 `0.167.0-alpha.4.1`。每组一次，240 秒外部时间上限，每题要求短理由；CLI 默认输出 token 上限及服务端实际模型修订未独立核验。固定先候选、后基线，不以延迟或 token 用量推断性能优劣。

每次调用前后核对参考正文、prompt、题面、评分、共享指令和本地配置的摘要。保留原始会话、stderr、完整参数及配置指纹在本机忽略目录，不上传机器配置。共同宿主/仓库规则保持生效，两组都可能受到当前公共上下文和 Skill 发现目录影响；不使用 ignore-rules、ignore-user-config 或更换宿主来消除这一限制。因此这是一组固定正文的文本情境对照，不是正式 7.0 安装环境对 7.1 的实操作用隔离试验。

客观检查继续使用 `grade.cjs`：标签匹配只说明字段选择；零工具调用、无文件修改及无失败才可计为完成的文本回答。两组共用允许标签，不因结果修改 oracle 或重跑追分。理由另外由新调用的 Judge 按事先 rubric 复核，匿名 X=候选、Y=基线；Judge 不看版本或评分结果。任何标签/语义分歧单列待人工复核，不把 Judge 当人工结案。

不要求工具调用，不重试 `registered Core launch requires an installed app` 的旧探针。若模型自行调用工具，保留实际记录并停止将该组视为纯文本对照，不换工具补跑。结果持平、标签未命中或无法判断都保留原结果，不自动改主 Skill。
