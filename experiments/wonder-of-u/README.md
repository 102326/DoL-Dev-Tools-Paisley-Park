### 同名导出覆盖的教训

真实摩擦发生在项目自己的 collector：同一下载目录中，第三次同名导出覆盖第二次文件，collector 仍只等新文件名而超时。初次失败摘要仍在；被覆盖的第二份原始下载已丢失，不能用摘要或后续结果重造为原件。

collector 已改为每次导出创建独立新子目录，再执行导出并读取该目录。最终四次导出的四份 JSON 均存在且可解析；后续成功不抹掉初次超时或原件丢失。

这已被 [DEVELOPMENT_FLOW 的证据接续规则](../../docs/DEVELOPMENT_FLOW.md#关联已有证据)覆盖：重复阶段保留独立输出，不用固定文件名覆盖旧成功或失败。案例具体落实到逐次下载目录即可，不需要再增加 Skill 警告、反馈系统或 GE 运行功能。
