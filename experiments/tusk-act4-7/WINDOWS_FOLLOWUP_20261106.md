## Delivered

源码查询使用本地 Git 对象时，原实现清除了外部 `GIT_*` 配置，却没有主动禁止 Git 自行补取 promisor 对象。`ls-tree -l` 在检查被排除路径的大小时也可能抓取缺失对象。

仅在现有共享 Git 子进程入口增加内部 `GIT_NO_LAZY_FETCH=1` 和空 `GIT_ALLOW_PROTOCOL` 白名单；CTS 与原生 TS 对照保持一致，CJS 由原 Program 生成。没有引入进程管理器、调整预算或放宽 partial、旧回执、原生代次及 GER 合同。配置依据为 [Git 官方环境变量说明](https://git-scm.com/docs/git#Documentation/git.txt-GITALLOWPROTOCOL)。源码获取仍由另一次明确操作完成，查询不代为联网。

回归使用自有中性 promisor 仓库，覆盖排除对象不被取回、合格源码缺失仍为 unreadable / partial，以及仓库允许 file 协议、模拟关闭 NO_LAZY_FETCH 时仍禁止取对象。最后一项会因元数据不可得而拒绝，不要求它制造完整结果。独立只读复核未发现本修复的新阻断；复核方没有运行测试或操作设备。

1. 首轮实验把 revision 放进 query JSON，CLI 在读取源码前返回 `SOURCE_REQUEST_INVALID`；随后改用已有 `--revision` 参数，保留原请求和错误。没有改 CLI 来接受错误输入。
