# Paisley Park 5.0：后半程当前进展

A/B 的有限原型验收保留。C 已完成真实任务复盘，以及 2026-10-14 的平板只读接续核对，达到**代表性接续范围 Scoped Done**。这表示后半程 V1.0 的约定范围收口，不表示正式 5.0 已打包或发布，也不表示完整 Mod 修复闭环已验收。

异常打赏案例有原始数据：同一游戏时间内，文章收入能随页面渲染重复增加；有界调用原回调后累计超过 £10,000。它不是已复现单笔 £10,000，最初怀疑的“多乘一次 100”也被实际增量排除。原任务只要求诊断，没有制作修复包；不能把原包安装成功说成漏洞修复成功。

真实调查已经自然用了标准 Dev Tools、源码检查和直接 CDP，无需新增 GER Goal。值得改进的是接续证据：原脚本按页面首项取目标，未逐阶段留存文档身份，相同阶段文件还可能覆盖旧记录。这些不足不能事后补造。

本轮只加了[按需接续 Recipe](DEVELOPMENT_FLOW.md)和 Skill 短链接，帮助后续任务复用现有绑定、重读当前对象、引用原证据并保留重复阶段结果。没有新增 Runtime、Ledger、全局锁或依赖；已有正常方法继续可用。

平板连接后，复用标准 Action 启动已授权测试 App，再使用已有生产文档绑定，读取实际版本、资源摘要和 UI 存储包；核对本地源码身份、当前制品和历史备份。全过程记录同一文档与原生资源身份，清理自有连接和转发。

发现一个真实加载差异：平板和本地包都叫 `3.0.0-stone-free.1`，但平板运行的是此前备份的旧字节，不是当前研发包。存储 ZIP、加载 JS/CSS 与 DOM 注入内容一致对应旧包；这证明“同版本号”不足以确认最新版已加载。没有重新安装、重新打赏或操作存档，也没有改 UI 源码。

本轮只增加文档与 Skill 的按需短入口。Skill 格式、安装/resolver 与隔离安装的既有检查复用；实际平板身份、制品正反例与资源清理通过。历史打赏身份缺口仍保留，完整修复/构建/部署后的业务复验仍为 Not validated。C-EXT 的重诊断、rrweb、性质测试等没有触发，继续作为可选工具箱。

技术范围和证据限制见 [C 复盘](PAISLEY_PARK_5_0_C_REVIEW.md)。全局安装仍为稳定 4.0.1，本轮本地资料没有推送或发布。
