# MapleBirch：版本允许、注册成功与实际显示要分开

状态：历史案例，2026-10-15 核对原报告；不是 6.0 新设备验收。对象为 LyraMouthCompat051213 0.1.1→0.1.2，Lyra 0.5.12.13-1.0.1a-1004.1-goose-ucb、MapleBirch 5.4.2、ModLoader 2.101.1。

## 发生了什么

旧包只允许框架 5.2.3，在 5.4.2 上由自身版本门禁退出。现场读取真实 `char.use` 后发现角色 main 图层契约仍在；不能因此认定 MapleBirch API 已破坏。0.1.2 放宽到稳定版 `>=5.2.3 <6.0.0`，同时保留能力检查和精确 Lyra 资源门禁。

修复只注册 `mouth.srcfn`，没有替换 `showfn`、角色变量、库存或 UI Runtime。历史验证经原安装入口导入、重启并检查实际侧栏模型采用情况：mouth 可见、图片成功解码、原 showfn 身份保留。最初后台 App 的 CDP 超时和被日志挡住的截图属于调查过程，不证明框架缺陷。

## 下次如何调查

依次核对包/框架实际版本、Manifest 依赖、脚本自己的门禁、扩展能力、注册记录、最终缓存模型采用和实际显示。某一步通过不能替代后面的证据。修源后按目标工程自己的打包方式构建，并核对实际加载成员摘要；不直接改第三方业务状态。

同主版本范围是兼容策略。5.4.2 的设备结果不能外推 5.4.3、全部 5.x 或其它角色图层 Mod；未来版本的替身门禁测试也只证明门禁。若遇到不同结果，检查当前真实实现，不强行复用旧结论。
