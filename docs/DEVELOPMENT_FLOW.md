# 按需 Recipe：现场、源码与制品接续

用于一次任务跨越 Debug、源码/构建/加载，或复盘已有轨迹。复用项目现有报告和证据；这不是强制阶段、固定表单或新的执行服务。

## 选择足够的路线

只读调查、截图、CSS 或普通点击使用现有 Debug、Action/Journey、源码工具；需要持久目标、累计预算和未知副作用恢复时才使用 GER。Component Lab 用于真实组件的快速迭代，不证明游戏业务或正式包已加载。原任务只要求诊断时，可交付已证明的原因及未验证范围，不要求为了完成流程制造补丁或编译。

## 跨步骤保持正确对象

已有标准能力能覆盖时优先复用。直接 CDP/Playwright 可作灵活调查，但 `contexts()[0].pages()[0]`、相同 URL 或旧端口不是文档绑定。Android 需要生产绑定时复用 `scripts/lib/execution-context.cjs` 的 `create(options, overrides, settings)`、`ensureWebview()` 和 `finish()`：显式 serial/package/user，存在歧义时指定已核对的 target/socket。它保留当前 frame/loader/uniqueContext 的绑定；失效后建立新连接，不能让旧持有者自动跟随。

这是 Tools 内部现有入口，不是稳定公共 SDK 承诺；调用前核对所选版本源码。普通只读诊断可显式绑定当前文档，无需另建 Goal。使用外部工具则保留其实际 target/context、采集方式和限制，不把外部 UID/ref 自动换算成 Paisley 身份。

页面跳转、SugarCube moment 复制或 Runtime 对象替换后，重新读取当前 `State.variables` 与目标记录。旧对象引用可用于解释旧快照，不能用于证明新状态。观察实际可用 API，勿凭历史版本猜 `Story.forEach/filter` 或未暴露的全局。异步返回、安装 ACK、屏幕仍显示旧数字，分别核对，不盲目重发已派发操作。

## 关联已有证据

在现有报告中按实际需要引用：问题与授权、目标/文档身份、观察时段、工具与版本、已有 incident/Journey 或 GER Session/attempt、源码 revision/dirty 字节或原 ZIP 哈希、制品摘要、加载证据和独立结果。没有使用的标识不补造，也不另建 Ledger。文件原哈希与命令引用帮助复核；相关不等于因果。

重复同一阶段时保留独立输出或现有检查点，不用固定文件名覆盖旧成功/失败；旧脚本和当前源码有差异时说明适用版本。已有报告足以关联时不新建记录服务。

诊断假设要能被观察区分，例如货币单位与累计收益、真实页面渲染与直接原回调、当前业务结果与 UI 刷新。保留失败及其归属；有已证实原因再修输入或方法，不重复无变化的调用到绿。源码修改、构建成功、存入包、实际加载、业务复验是不同证明；缺其中一项就如实标记。同版本号也可能对应不同字节；遇到加载疑问，按需比对当前制品、存储包和加载资源，而不是为统一版本直接重装。

## 恢复与收口

已派发且结果 Unknown 的动作由原链路恢复；直接 Debug 不能盲重放，换 Store 或当前合同不能结清旧事实。可以继续无冲突的读取和独立源码工作。

清理只涉及本轮自有资源，并记录不确定或冲突；端口当前存在不等于仍属于本轮。结束以任务承诺判断：完整诊断不等于修复完成；缺原始身份轨迹不能事后补造连续性。分开写 Delivered、Validated、Not validated、Known limitations。
