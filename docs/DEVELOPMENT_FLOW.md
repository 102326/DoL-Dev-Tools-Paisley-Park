# 按需 Recipe：现场、源码与制品接续

用于一次任务跨越 Debug、源码/构建/加载，或复盘已有轨迹。复用项目现有报告和证据；这不是强制阶段、固定表单或新的执行服务。

## 选择足够的路线

只读调查、截图、CSS 或普通点击使用现有 Debug、Action/Journey、源码工具；需要持久目标、累计预算和未知副作用恢复时才使用 GER。Component Lab 用于真实组件的快速迭代，不证明游戏业务或正式包已加载。原任务只要求诊断时，可交付已证明的原因及未验证范围，不要求为了完成流程制造补丁或编译。

## 跨步骤保持正确对象

研究Mod时，尽量先核对作者最新正式发布，下载到隔离目录后再研究。区分正式附件、对应源码、默认分支HEAD与设备当前版本；记录来源、核对时间和摘要。没有正式附件或无法确认官方来源时如实说明，不把源码ZIP当成可安装包。获准更新测试目标时先备份原包与配置，再核对持久化、重载和实际功能；新结果不改写旧版本证据。当前输入见[Mod来源记录](knowledge/latest-mod-sources.md)。

已有标准能力能覆盖时优先复用。直接 CDP/Playwright 可作灵活调查，但 `contexts()[0].pages()[0]`、相同 URL 或旧端口不是文档绑定。Android 需要生产绑定时复用 `scripts/lib/execution-context.cjs` 的 `create(options, overrides, settings)`、`ensureWebview()` 和 `finish()`：显式 serial/package/user，存在歧义时指定已核对的 target/socket。它保留当前 frame/loader/uniqueContext 的绑定；失效后建立新连接，不能让旧持有者自动跟随。

这是 Tools 内部现有入口，不是稳定公共 SDK 承诺；调用前核对所选版本源码。普通只读诊断可显式绑定当前文档，无需另建 Goal。使用外部工具则保留其实际 target/context、采集方式和限制，不把外部 UID/ref 自动换算成 Paisley 身份。

页面跳转、SugarCube moment 复制或 Runtime 对象替换后，重新读取当前 `State.variables` 与目标记录。旧对象引用可用于解释旧快照，不能用于证明新状态。观察实际可用 API，勿凭历史版本猜 `Story.forEach/filter` 或未暴露的全局。异步返回、安装 ACK、屏幕仍显示旧数字，分别核对，不盲目重发已派发操作。

## 关联已有证据

在现有报告中按实际需要引用：问题与授权、目标/文档身份、观察时段、工具与版本、已有 incident/Journey 或 GER Session/attempt、源码 revision/dirty 字节或原 ZIP 哈希、制品摘要、加载证据和独立结果。没有使用的标识不补造，也不另建 Ledger。需要核对输入来源、制品同一性或履行发行合同时，文件原哈希与命令引用帮助复核；相关不等于因果。不要为普通源码任务追加整套指纹，也不要重复哈希本轮未变的输入。

先从当前报告的对应结论找到它引用的摘要、manifest 和具体制品，再按缺口读取原始日志。保留摘要的采集时段与范围：旧摘要的待验字段不是当前任务状态，筛选后的时间线也不是全部命令。总计、映射行和遗漏分别解释，不为凑齐关联补造事件。跨 Debug/GER 时引用原 Session/attempt；未使用 GER 的调查不填写虚构标识。现有记录已足够时无需生成额外表单。

重复同一阶段时保留独立输出或现有检查点，不用固定文件名覆盖旧成功/失败；旧脚本和当前源码有差异时说明适用版本。已有报告足以关联时不新建记录服务。

诊断假设要能被观察区分，例如货币单位与累计收益、真实页面渲染与直接原回调、当前业务结果与 UI 刷新。保留失败及其归属；有已证实原因再修输入或方法，不重复无变化的调用到绿。源码修改、构建成功、存入包、实际加载、业务复验是不同证明；缺其中一项就如实标记。同版本号也可能对应不同字节；遇到加载疑问，按需比对当前制品、存储包和加载资源，而不是为统一版本直接重装。

做解压包依赖验货时，检查执行进程实际解析到哪份依赖；源码树里的解压目录可能借用祖先依赖。该类调查的最小方法见 [安装验货边界](SKILL_INSTALL.md#解压包的依赖隔离检查)。本轮具体的历史摘要、平板接续与候选关联见 [C 后续证据导航](PAISLEY_PARK_5_0_C_FOLLOWUP.md)，无需普通诊断每次都阅读这些案例。

重建目标项目时，按实际需要保留根配置、锁文件、调用 CWD 和工具来源；只复制入口源码可能遗漏编译器隐含输入。字节不匹配时先定位差异，不因版本号相同、函数相似或仅差注释就宣布制品相同。[真实构建差异案例](knowledge/build-byte-drift.md)提供一个有边界的调查过程，不要求每次诊断都重建。

## 验证选择与停止

MSV（最小充分验证）面向当前工程决定与完成声明，不是额外审批或报告阶段。局部修改直接检查受影响行为；Bug优先复现触发条件，再检查修复与必要的相邻行为；公共机制变化才扩大到实际消费者和生命周期。已有检查快速、稳定且覆盖关键风险时直接运行，不为少跑一条检查增加更贵的分析或表格。总成本包括准备、执行、失败调查与返工，不只比较测试条数。

复用证据要看它所依赖的输入，而非只看日期或版本号：Skill文案修改不使原Android业务证据失效，安装器变化却需要受影响的安装检查；新构建的ZIP不能沿用旧ZIP摘要。配置装配已有输入/输出内容断言时，未变测试和历史夹具的反复哈希不增加该结果的行为证据；需要证明未修改受保护文件时，已有可信diff或字节记录足够就复用。一次任务内未变的工具定位和环境不必反复冒烟，但旧页面、对象或执行绑定不能借此当成当前现场。原结果、失败和未验证范围仍按原来源保留，不为统一报告数字重跑。

构建与装配修改核对受影响的输入、输出及任务需要的加载身份；普通源码修复不自动要求完整制品清单、设备重装或全业务回归。正式候选仍遵守既有 [发布包验货](RELEASE_PACKAGE.md)与 [安装合同](SKILL_INSTALL.md)，MSV不豁免这些要求。

所选检查支持当前承诺且没有尚未处理的关键风险时，以Scoped Done交付并停止追加验证；可选覆盖不是剩余必做项。出现新现实风险、需要区分重要假设或正式发布合同要求时，再增加对应检查。必要的资源、权限或证据缺失时，相关结论是Blocked/Inconclusive，说明具体缺口后停止该验证；不把未验业务写成通过，也不无限替换工具或扩张测试。能独立完成的源码/诊断工作仍可交付。

可选分析器不覆盖、Unknown或超时，不阻断原本可用的源码调查、Debug与正常测试路线。分析未知不是已派发副作用的GER Unknown；它不能结清、重放或改写历史执行事实。未知Mod没有专属适配器时，仍可从授权源码、通用观察和项目已有工具调查。

## 恢复与收口

已派发且结果 Unknown 的动作由原链路恢复；直接 Debug 不能盲重放，换 Store 或当前合同不能结清旧事实。可以继续无冲突的读取和独立源码工作。

清理只涉及本轮自有资源，并记录不确定或冲突；端口当前存在不等于仍属于本轮。结束以任务承诺判断：完整诊断不等于修复完成；缺原始身份轨迹不能事后补造连续性。分开写 Delivered、Validated、Not validated、Known limitations。
