# 7.2 发布执行纠正

这是正式发布后的维护记录，不是重新发布或更换 7.2 成品。固定 Release 为 [v7.2.0](https://github.com/102326/DoL-Dev-Tools-Paisley-Park/releases/tag/v7.2.0)，源码仍为 `a8b1dfa235c6ece17d10ef4a3f47c5f658832449`。

## 原失败与实际影响

首个 7.2 候选的隐私扫描在 `docs/WINDOWS_5_1.md` 命中历史工程路径。用户独立复核确认该路径已存在于原公开 7.0，不含真实姓名、个人邮箱或凭据；移除新包中的这条路径是正常脱敏，不意味着能够抹除公开历史。

扫描的 Python 断言返回非零，但组合 PowerShell 命令没有在原生命令后显式检查退出码，后面的 Git 命令仍执行，main 因而提前快进到 `11ab4f2088d93b937946efbe82e475ca6c05ee51`。这是实际执行失误，不能写成检查一直无误；当时还没有创建 Tag 或 Release。

随后正常补丁提交移除当前文档中的路径，未重写历史。原失败候选、错误和提前快进记录保留本地。最终只使用第二候选，7.0 的资产与摘要未变。

## 后半程实际采用的保护

- 最终候选的构建、隐私/解压检查、隔离安装及匹配 CI 分成独立步骤，原生命令后显式核对退出码；检查失败时不继续执行依赖的发布命令。
- 不只看文件存在或退出 0：核对 ZIP 的实际内容/摘要、安装位置与自身依赖，以及 CI 返回的 success 和完整 head SHA。
- main、Tag 和 Release 操作逐项检查；正式创建 Release 前，另外核对 main/Tag 的 CI 都对应最终来源并成功。
- 创建后再次读取正式状态、Tag/main 指向及服务器摘要，匿名下载三份附件，逐字节比较实际验货文件；没有靠上传退出码宣布完成。

现在将这条约束固化到 AGENTS 和[发布合同](../../RELEASE_PACKAGE.md#发布执行必须失败即停止)，不新增权限服务或发布平台。

## 本轮失败即停止自检

复用本机 PowerShell 和 Node，以真实 7.2 ZIP 计算摘要；测试下游仅为本轮本地合成标记，不含 Git 推送、Tag 或 Release 命令。

| 输入 | 实际结果 |
| --- | --- |
| 原生命令退出 23，但返回看似 passed 的 JSON | 外层立即检查退出码并终止，未产生下游标记。 |
| 原生命令退出 0，但结果 status=failed | 结构化结果检查终止，未产生下游标记。 |
| 退出 0，状态及固定源码/ZIP 摘要匹配 | 只产生合成本地标记，作为正对照。 |

两个失败分支还核对具体错误分别为 CHECK_NATIVE_EXIT_23 与 CHECK_RESULT_INVALID，避免将无关启动失败算成保护生效。原始命令、日志和三个结果留在忽略目录 `artifacts/release-7.2.0/fail-stop-check/`。这证明所用原生命令控制流程，不宣称所有未来脚本已经自动加上检查。
