# TypeScript developer build

Node sources compile to the existing CommonJS paths. Installed users run the checked-in CJS and browser JS; this directory and authoritative TS are excluded from the runtime archive. Root dependencies and Node requirements do not change.

```sh
npm ci --prefix tools/typescript --ignore-scripts --no-audit --no-fund
node tools/typescript/build.cjs --check
node tools/typescript/check-types.cjs
node --test tools/typescript/test/*.test.cjs
# Only after reviewing an intentional authoritative source edit:
node tools/typescript/build.cjs --write-production
```

`tsconfig.json` lists the authoritative Node CTS entry files. `browser-tsconfig.json` lists DOM-only functions in `probes/typescript`; it has DOM/DOM.Iterable and an empty types list, while the Node Program retains ES2022 plus Node types. TypeScript6.0.2 checks and emits both complete Programs in memory, with strict and noEmitOnError. The default config itself has noEmit, so direct tsc checking does not overwrite runtime files. Outputs have LF-normalized source digests and full-byte comparison; checkout CRLF is accepted. `source-find.mts` is a generated comparison input for the existing opt-in native experiment; its source of truth is `source-find.cts`. It is not an ESM product entry or a second implementation.

The leaf modules use standard TypeScript `export =` to retain the exact existing CJS export shape, without adding an `__esModule` marker. Unlike the earlier native-stripping experiment, this compiled build permits that syntax and therefore does not set erasableSyntaxOnly. It does not introduce runtime enums, decorators or a runtime TS loader. Node types stay at the existing locked25.9.5; their presence does not prove support for every Node26 API. Exact minimum-Node runtime evidence remains required.

`--check` is read-only and never cleans an output directory. Generation first validates the entire emission, then stages and verifies every changed artifact and backup on its destination filesystem. It preserves existing permission modes (new outputs default0644), coordinates cooperating builders using exclusive `.paisley-ts-build-lock`, rechecks captured source inputs and publishes the known outputs. On an ordinary later publication failure, it restores earlier outputs only while their observed identities and bytes still match. Unknown peer changes keep their bytes and retain backups for recovery.

This is not an atomic multi-file transaction or a filesystem compare-and-swap. Arbitrary external editors can race between checks and rename; do not edit generated outputs during generation. The lock coordinates this generator, not every process on the computer. No automatic stale-lock removal, PID-based ownership guessing, recursive sweep or permission workaround is performed. If interrupted or cleanup is uncertain, preserve the output/staging/lock, inspect ownership and retained backups, then use a verified new checkout or explicitly reviewed recovery before generating again. A check can safely report drift while another writer publishes; it does not adopt that partially published set as valid.

The existing `PAISLEY_TSC` and `PAISLEY_TYPE_ROOTS` process overrides accept a reviewed matching compiler/type tree. No global installation or configuration is changed. Old experiment commands delegate here; installing the formal tool package is preferred over maintaining separate experiment dependencies.

Browser functions emit to `scripts/lib/browser/*.cjs`, with generated `.d.cts` for development. The Node Program consumes these declarations from the in-memory emission before any publication, so it does not acquire DOM globals. Only the generated functions are injected through the existing expression builders; the CommonJS module wrapper is not sent to the page. CSS properties remain an explicit injected argument, and direct Node snapshot calls retain their module default. Sources and declarations stay out of the runtime archive; generated browser CJS is required payload. Both Programs must pass before the existing shared publication/rollback begins.

This initial browser split covers structural DOM/CSS probes. It does not migrate native business function fingerprints or establish new receipt contracts. Those owners require separate source/digest and recovery validation. `contract()` returns only fields its runtime checks establish; for example, CSS style keys can be absent and DOM contract metadata remains opaque.

Digest-sensitive browser ABI inputs are a separate role from compiled probes. `scripts/lib/browser-abi/native-render-tasks.cjs` retains the original two function bodies verbatim because their `Function.prototype.toString` text participates in the existing render digest. Its Node coordinator is strict CTS; these JavaScript bodies are intentionally not compiler output or counted as typechecked browser sources. The boundary exposes unknown results, without a runtime loader, replacement `toString` or a new evaluator. The fixed original source compatibility test checks exact function text, emitted protocol frames, digest and rejected preflights. These inputs remain required archive payload; a deliberate source edit needs its own contract and old-pending recovery decision. The build's Program check alone does not validate these frozen inputs.

Browser ABI inputs and their fixed original oracle explicitly use Git `text eol=lf`. The render test also pins the existing LF Git-blob digest, so converting both sides to CRLF cannot hide drift. This preserves the original LF archive contract; it does not migrate historical receipts from a CRLF checkout. Such records keep their original identity and require their original compatible recovery baseline, never automatic settlement under a newly computed digest. Windows checkout behavior still needs actual validation.

`browser-abi/native-business-bindings.cjs` likewise retains the original `checkBindings` guard text used inside native wardrobe/shop contract sources. Its Node binder is strict CTS and requires the reviewed `updateMoment` profile entry. Retained attestation overloads expose the fields actually constructed when `retain:true`; remote object IDs stay unknown. Both the ABI file and its fixed original oracle are LF, with an independently pinned guard digest. These three frozen functions across two inputs are not counted as typechecked browser bodies.

`browser-abi/native-shop.cjs` preserves four additional source-sensitive shop functions. The wardrobe/shop Node preparation coordinators are strict CTS and distinguish attestation-only results from executable reviewed operations; their raw page snapshots and remote IDs remain unknown. Existing JS producers are represented by bounded local ports pending their own migration, without granting new runtime validation. Seven frozen function bodies across three inputs are not counted as typechecked DOM sources. Fixed original modules compare complete preparation frames, guard/operation text, binding digests and cleanup outcomes.
