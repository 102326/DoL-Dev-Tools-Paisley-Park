# TypeScript developer build

Node sources compile to the existing CommonJS paths. Installed users run the checked-in CJS and browser JS; this directory and authoritative TS are excluded from the runtime archive. Root dependencies and Node requirements do not change.

```sh
npm ci --prefix tools/typescript --ignore-scripts --no-audit --no-fund
node tools/typescript/build.cjs --check
node tools/typescript/check-types.cjs
node --test tools/typescript/test/*.test.cjs
# Only after reviewing an intentional authoritative source edit:
node tools/typescript/build.cjs --write-production
```

`tsconfig.json` lists the authoritative Node CTS entry files. `browser-tsconfig.json` lists DOM-only functions in `probes/typescript`; it has DOM/DOM.Iterable and an empty types list, while the Node Program retains ES2022 plus Node types. TypeScript6.0.2 checks and emits both complete Programs in memory, with strict and noEmitOnError. The default config itself has noEmit, so direct tsc checking does not overwrite runtime files. Outputs have LF-normalized source digests and full-byte comparison; checkout CRLF is accepted. `source-find.mts` is a generated comparison input for the existing opt-in native experiment; its source of truth is `source-find.cts`. It is not an ESM product entry or a second implementation.

The leaf modules use standard TypeScript `export =` to retain the exact existing CJS export shape, without adding an `__esModule` marker. Unlike the earlier native-stripping experiment, this compiled build permits that syntax and therefore does not set erasableSyntaxOnly. It does not introduce runtime enums, decorators or a runtime TS loader. Node types stay at the existing locked25.9.5; their presence does not prove support for every Node26 API. Exact minimum-Node runtime evidence remains required.

`--check` is read-only and never cleans an output directory. Generation first validates the entire emission, then stages and verifies every changed artifact and backup on its destination filesystem. It preserves existing permission modes (new outputs default0644), coordinates cooperating builders using exclusive `.paisley-ts-build-lock`, rechecks captured source inputs and publishes the known outputs. On an ordinary later publication failure, it restores earlier outputs only while their observed identities and bytes still match. Unknown peer changes keep their bytes and retain backups for recovery.

This is not an atomic multi-file transaction or a filesystem compare-and-swap. Arbitrary external editors can race between checks and rename; do not edit generated outputs during generation. The lock coordinates this generator, not every process on the computer. No automatic stale-lock removal, PID-based ownership guessing, recursive sweep or permission workaround is performed. If interrupted or cleanup is uncertain, preserve the output/staging/lock, inspect ownership and retained backups, then use a verified new checkout or explicitly reviewed recovery before generating again. A check can safely report drift while another writer publishes; it does not adopt that partially published set as valid.

The existing `PAISLEY_TSC` and `PAISLEY_TYPE_ROOTS` process overrides accept a reviewed matching compiler/type tree. No global installation or configuration is changed. Old experiment commands delegate here; installing the formal tool package is preferred over maintaining separate experiment dependencies.

Browser functions emit to `scripts/lib/browser/*.cjs`, with generated `.d.cts` for development. The Node Program consumes these declarations from the in-memory emission before any publication, so it does not acquire DOM globals. Only the generated functions are injected through the existing expression builders; the CommonJS module wrapper is not sent to the page. CSS properties remain an explicit injected argument, and direct Node snapshot calls retain their module default. Sources and declarations stay out of the runtime archive; generated browser CJS is required payload. Both Programs must pass before the existing shared publication/rollback begins.

The initial D01 browser split covered structural DOM/CSS probes. Later batches separately handle ordinary readers and preserve native fingerprint inputs; no new receipt contract is established by compilation alone. `contract()` returns only fields its runtime checks establish; for example, CSS style keys can be absent and DOM contract metadata remains opaque.

Digest-sensitive browser ABI inputs are a separate role from compiled probes. `scripts/lib/browser-abi/native-render-tasks.cjs` retains the original two function bodies verbatim because their `Function.prototype.toString` text participates in the existing render digest. Its Node coordinator is strict CTS; these JavaScript bodies are intentionally not compiler output or counted as typechecked browser sources. The boundary exposes unknown results, without a runtime loader, replacement `toString` or a new evaluator. The fixed original source compatibility test checks exact function text, emitted protocol frames, digest and rejected preflights. These inputs remain required archive payload; a deliberate source edit needs its own contract and old-pending recovery decision. The build's Program check alone does not validate these frozen inputs.

Browser ABI inputs and their fixed original oracle explicitly use Git `text eol=lf`. The render test also pins the existing LF Git-blob digest, so converting both sides to CRLF cannot hide drift. This preserves the original LF archive contract; it does not migrate historical receipts from a CRLF checkout. Such records keep their original identity and require their original compatible recovery baseline, never automatic settlement under a newly computed digest. Windows checkout behavior still needs actual validation.

`browser-abi/native-business-bindings.cjs` likewise retains the original `checkBindings` guard text used inside native wardrobe/shop contract sources. Its Node binder is strict CTS and requires the reviewed `updateMoment` profile entry. Retained attestation overloads expose the fields actually constructed when `retain:true`; remote object IDs stay unknown. Both the ABI file and its fixed original oracle are LF, with an independently pinned guard digest. These frozen functions are not counted as typechecked browser bodies.

`browser-abi/native-shop.cjs` preserves four additional source-sensitive shop functions. The wardrobe/shop Node preparation coordinators are strict CTS and distinguish attestation-only results from executable reviewed operations; their raw page snapshots and remote IDs remain unknown. The original migration used bounded temporary ports; current consumers now reference their migrated producer types, without granting new runtime validation. These source-sensitive function bodies are not counted as typechecked DOM sources. Fixed original modules compare complete preparation frames, guard/operation text, binding digests and cleanup outcomes.

The clothing mapping producers (`game-wardrobe` and `game-shop`) now supply authoritative request and preparation types to their native coordinators, replacing the temporary mapping ports. Attestation is explicitly nonterminal; raw interpretation values stay unknown. Their three source-sensitive browser functions remain in `browser-abi/wardrobe-mapping.cjs` and `shop-mapping.cjs`: the mapping function bodies are not typechecked DOM sources. Independent LF digests and fixed old-module protocol/receipt comparisons guard those boundaries.

`game-native-control` and `game-native-navigation` provide strict source/closure ownership ports. `lexical` and attestation require only CDP send; navigation preparation additionally requires evaluate for the receipt context. Lexical values and returned selected Action remain unknown until the downstream validation that owns them. Control types now replace the temporary ports in the clothing modules. `browser-abi/native-control.cjs` preserves the original event reader text: these function bodies remain outside DOM typechecking. The native history/save/operation producers are now migrated separately with their original source roles preserved.

History, native save and environment coordination now consume actual producer types. Receipt projections and falsey evidence-validation results remain unknown, because the historical helpers do not validate every raw field. Source-sensitive history/save/environment functions retain their original JavaScript text and receiver closures: these function bodies remain outside DOM typechecking. Source/digest and full protocol comparisons guard that intentional source role.

Finite native receiving guards and four native operation modules now have authoritative CTS source-carrier interfaces. They are serialization inputs, not Node executors: the interface exposes toString, not a callable signature. Their original browser bodies remain required raw protocol inputs because existing guard/operation text determines receipt contracts. Five additional assets contain thirteen original bodies (one shared finite-state asset plus four operation assets); these bodies are intentionally outside DOM typechecking. These nine Node entries are source carriers, not claims that their browser implementation was typechecked.

Host tools, CLI and optional Integration entry points also use CTS. Seven additional ordinary probes (recording, timeline and Integration readers) use the DOM-only Program; their function text is not a persisted receipt identity and their behavior is checked against original fixtures. The optional native-head operation remains one additional frozen receipt ABI, for 37 untyped source bodies across fifteen inputs. Integration CTS/declarations stay out of the runtime archive, while its frozen ABI and central generated browser CJS remain required payload. CLI now references the actual migrated Goal/Provider/Evidence owners through lazy requires. Legacy dynamic preparation derives its argument tuple and return union from the actual shop/wardrobe producers, preserving JavaScript ignored-extra-argument behavior without a parallel Mapping schema.


## Complete Mac migration scope

All 95 original Node entry points now resolve authoritative CTS in the strict Program. Nine are source carriers; their Node API intentionally serializes browser code rather than claiming the underlying browser algorithm is typechecked. There are 17 genuinely DOM-only typed sources and 21 frozen JavaScript ABI inputs containing 46 untyped function bodies. The runtime inventory is 133 entries. This is a source-role distinction, not a TypeScript loader or a new recovery contract.

`build.cts`, `check-types.cts` and `test/build.test.cts` are also authoritative. The checked-in CJS build can compile and publish itself using the existing same-filesystem staging/rollback protocol; installed runtime packages do not need this tool. Its complete Node Program has 98 entries (95 runtime plus these three developer entries), and both Programs produce 133 checked artifacts, including declarations and the native comparison file. These artifact and runtime counts describe different sets.

The type checker retains the original 117 expected errors and adds eight focused record/ABI/owner boundary errors. The generated build test suite retains five portable checks: complete Program drift and invalid types, staging/publication failures and mode restoration, observed peer replacement, exclusive cooperative lock, and DOM/Node global separation. A sixth, Windows-only check uses installed PowerShell 7 to hold real `FileShare.None` and `FileShare.Read` handles over isolated CJS copies. It checks native read/rename refusal, exact previous bytes after rollback, peer preservation, handle release and successful regeneration. Successful publication emits LF; failure preservation remains byte-for-byte. Other platforms skip this Windows check. Synthetic invalid JS inputs, fixed original ABI oracles, dated experiment records, Python/Kotlin and test-driver glue keep their existing roles; no second runner or mass test-language conversion is added.

Runtime Session/effect JSON is exposed as unknown where the old code has no complete schema proof. Local access views do not replace checks. The config boundary now validates a stable structured snapshot and compares the actual JSON projection, so direct API hooks/getters cannot silently enlarge the inspected budget or drop/expand scope. Plain JSON remains supported; executable/non-JSON configurations are not a permission sandbox. This fixes a local API consistency defect, not a demonstrated remote CLI exploit. No old pending effects are settled, replayed or migrated.

Mac synthetic tests and Chrome evidence do not establish Windows file-lock/rename, Android/WebView or real-game acceptance. Source-sensitive bodies remain frozen and untyped. See the fixed-code and package records in the current [migration progress](../../experiments/tusk-act4-7/typescript/PROGRESS.md).
